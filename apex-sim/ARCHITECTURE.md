> 전제: [KICKOFF.md](KICKOFF.md) Q1 추천안 **웹 버전**(C++20 물리 코어 → WASM, Three.js WebGPU 렌더러).

## A§1. 설계 원칙 → 아키텍처 결정

| 원칙 (§1) | 아키텍처 결정 |
|---|---|
| 1. 물리가 먼저 | 모든 운동·손상은 `SoftBodyCore`가 계산한다. 렌더러는 노드 위치를 받아 그릴 뿐 운동을 만들지 않는다. 카메라 흔들림도 차체 가속도 측정값에서 유도한다 |
| 2. 보이는 것 = 물리 | 방지턱·연석·포트홀은 메시 형상, 미세 요철은 물리·렌더가 공유하는 결정론 함수로 만든다(KICKOFF C6). 충돌 메시와 비주얼 메시는 같은 소스 데이터에서 생성한다 |
| 3. SI 단위 | 코어 API는 전부 SI다. 표시 단위 변환은 `web/src/ui/units.ts` 한 곳에서만 한다 |
| 4. 데이터 드리븐 | 차량·재질·맵·모드·튜닝은 `data/` 아래 JSON이다. 코어 상수는 `constexpr` + 이름·단위·근거 주석(§1.4) |
| 5. 결정론 | 고정 dt, 스텝 번호 기반 시간, 자체 초월함수, 결정론적 병렬 합산, 상태 해시(A§4.5) |
| 6. 쉬운 조작 + 깊은 설정 | 보조·필터는 코어 안(결정론 보장)에서, 프리셋은 데이터로 둔다 |
| 7. 오리지널 IP | 차량 생성기와 브랜드 이름 생성기가 가상 브랜드를 만든다 |
| 8. 구현된 척 금지 | 기능 플래그에 `implemented / stub / temp` 상태를 두고, 미구현 기능은 UI에 "미구현" 배지를 표시한다. KNOWN_ISSUES.md 자동 대조 |

```

│  App/State  ─ UI (DOM · Preact) ─ HUD ─ i18n/units                │
│  Input (Keyboard/Mouse/Gamepad/Pointer) → raw input samples        │

│   SimLoop 2000 Hz 고정 스텝 · 과부하 시 슬로다운(RTF 표시)          │

└───────▲────────────────────────────────────────────────────────────┘
        │ ④ 정적 충돌 셀(BVH blob) 로드·언로드
┌───────┴──────────────┐
│ Streaming Workers ×N │  fetch → 압축 해제 → 디코드 → (렌더 버퍼 / 물리 셀)
└──────────────────────┘

- **스레드 모델(§21.2):** 메인 스레드는 게임·UI·렌더, 물리 워커는 2000 Hz 루프, 워커 안의 pthreads 풀은 섬(island) 병렬 처리를 맡는다. 렌더를 `OffscreenCanvas` 워커로 옮기는 것은 M4 프로파일링 결과를 보고 결정한다.
- **통신:** 실시간 경로(①②)는 전부 SharedArrayBuffer + Atomics로 락 없이 처리한다. 비실시간 명령(③)은 SAB 메시지 큐를 쓴다(postMessage 지연 회피).

## A§4. 물리 코어 `SoftBodyCore`

### A§4.1 데이터 레이아웃 (SoA, §4.1 · §4.2 성능)

- **노드:** `pos[x,y,z]`(float32, 섬 로컬 좌표), `vel`, `force`, `invMass`, `radius`, `friction`, `materialId`, `partId`, `flags`(collision·fixed·tread 등).
- **빔:** 종류별로 **별도 SoA 배열**을 두고 커널을 분리한다(분기 없는 SIMD): `normal`, `support`, `bounded`, `anisotropic`, `rope`, `hydro`.
  - 공통 필드: `nodeA`, `nodeB`, `restLen`, `k`[N/m], `c`[N·s/m], `plasticF`[N], `breakF`[N], `deformLimit`[-], `preCompression`[-], `breakGroup`.
  - 상태 필드: `broken`, `plasticStrain`, `absorbedEnergy`[J].
- **삼각형:** 노드 인덱스 3개 + 플래그(collision·aero·buoyancy·pressure). 압력 그룹은 닫힌 삼각형 집합으로 표현한다.
- **힘 합산의 결정론:** 빔 힘은 빔 순서대로 SIMD 계산해 빔별 힘 버퍼에 쓴다 → 노드별 CSR 인접 목록(노드 → (빔, 부호))을 **고정 순서로** 모아 합산한다. 원자적 연산이 없어 스레드 수와 무관하게 결과가 같다.

### A§4.2 한 스텝(0.5 ms)의 파이프라인

```
 1  입력 적용         InputRing에서 해당 스텝 번호의 입력 → 보조 필터(결정론) → hydro 목표 길이·스로틀·브레이크·조향
 2  힘 초기화 + 중력
 3  빔 힘             종류별 커널, 감쇠 포함. 소성·파단 판정 결과는 "지연 이벤트"로 기록만 한다
 4  압력 그룹         발산 정리로 부피 V = Σ(1/6)·(a·(b×c)) → P = nRT/V → 삼각형 법선 방향 힘
 5  공력·부력         삼각형별 항력·양력, 수면 아래 삼각형의 정수압·항력 (A§4.9)
 6  타이어            접지면 집계 → 슬립 → Magic Formula → 접지 노드에 하중 비례 분배 (A§4.7)
 7  파워트레인        1D 회전 네트워크 적분 → 허브 노드에 토크를 우력(짝힘)으로 인가 (A§4.8)
 8  충돌              광역 → 노드↔삼각형·모서리↔모서리 페널티 + 쿨롱 마찰 (A§4.6)
 9  적분              symplectic Euler: v ← v + (F/m)·dt, x ← x + v·dt
10  CCD 보정          이번 스텝 이동 선분이 면을 가로지른 노드 → 면 앞으로 되돌리고 법선 속도 제거(에너지는 "접촉 손실"로 계상)
11  지연 이벤트 적용  소성(휴지 길이 갱신)·파단·breakGroup 연쇄 → 연결 성분 재계산 → 분리 부품은 새 섬으로
12  계측              KE·탄성 PE·중력 PE·소성 흡수·감쇠·마찰·접촉 손실·입력 일 누적, 운동량·각운동량, 충돌 이벤트 로그
13  게시              렌더 주기에 맞춰 RenderState 트리플 버퍼에 노드 위치·원점·시각 기록
```

### A§4.3 적분과 안정성 (§4.2)

- **적분기:** symplectic Euler, `dt = 0.5 ms` 고정. 시간은 `stepIndex × dt`로만 표현한다(벽시계를 쓰지 않음).
- **임계 시간 간격 검사기**(`sbc-cli check-stability`, 에디터 경고, 로드 시 검사):
  - 빔: `dt < s·(2/ω)(√(1+ζ²) − ζ)`, `ω = √(k/m_r)`, `m_r = m₁m₂/(m₁+m₂)`, `ζ = c/(2√(k·m_r))`
  - 노드: `dt < s·√(2·m_i / Σ_j k_ij)` (Gershgorin 원판 상한)
  - `s` = 안전계수(기본 0.8, 데이터로 조정). 위반한 빔·노드를 목록과 3D 하이라이트로 보여 준다.
- **[선택] XPBD·암시적 적분** 실험 경로는 `Integrator` 인터페이스 뒤에 두고, 파라미터는 N/m 단위를 유지한다.

### A§4.4 좌표계와 정밀도

- 섬(차량·분리 부품)마다 `origin`(double, 1 m 격자로 스냅)을 두고 노드는 float32 로컬 좌표로 저장한다. 섬 중심이 원점에서 64 m 이상 벗어나면 결정론적으로 재기준(rebase)한다.
- 정적 월드 셀도 셀마다 double 원점 + float32 정점을 쓴다. 충돌할 때는 `(셀 원점 − 섬 원점)`을 double로 계산해 float 오프셋으로 변환한다.
- 근거: float32는 8 km 부근에서 해상도가 약 1 mm라서 0.5 ms 스텝의 미세 이동(1 m/s일 때 0.5 mm)을 표현하지 못한다. 반면 16 m 부근에서는 약 2 µm다.

### A§4.5 결정론 (§1.5, §21.3)

| 위험 요소 | 대책 |
|---|---|
| 부동소수점 축약·재배열 | `-ffp-contract=off`, fast-math 금지. relaxed-SIMD 금지. 비정규수 유지(FTZ/DAZ 끔 — WASM 명세와 일치) |
| libm 차이 | `det_math`: sin·cos·atan2·exp·log·pow를 고정 다항식으로 자체 구현. `sqrt`는 IEEE 정확 반올림이라 그대로 사용 |
| 병렬 합산 순서 | 섬 단위로 병렬 처리하고, 섬 안에서는 고정 순서로 처리. 섬 간 접촉은 쌍 ID 정렬 순으로 직렬 합산 |
| 난수 | 서브시스템별 시드의 카운터 기반 RNG(SplitMix64/Philox). `Math.random` 금지 |
| 입력 타이밍 | 입력은 스텝 번호 태그를 달아 기록한다. 보조·스무딩 필터는 코어 안에서 실행한다 |
| 데이터 차이 | 리플레이 헤더에 차량·맵·재질 데이터 해시와 코어 버전을 기록한다 |

- **상태 해시:** N 스텝마다 노드 pos·vel 비트, 빔 상태, 파워트레인·타이어 상태를 xxHash64로 계산한다.
- **골든 리플레이(§2.8):** 입력 로그 + 기대 해시를 저장해 두고 CI에서 네이티브·WASM 양쪽으로 재생해 비교한다.

### A§4.6 충돌 (§5)

- **대상:** 차↔차, 차↔정적 월드(지형·건물·도로 시설), 차↔동적 오브젝트(가드레일·표지판 등도 노드-빔 섬), 자기충돌(서로 다른 부품 그룹 간), 분리 부품↔전부.
- **광역:** 섬마다 충돌 삼각형 동적 AABB 트리를 매 스텝 refit한다. 섬 간에는 섬 AABB로 SAP를 하고, 정적 월드는 노드 스윕 AABB로 셀 BVH를 질의한다(셀 BVH는 오프라인 SAH 빌드 후 스트리밍).
- **좁은 단계:** 노드(구, 반경 r)↔삼각형 최근접점, 충돌 삼각형 모서리↔모서리, 꼭짓점·모서리 영역 처리.
- **접촉력:** `F_n = k_c·d + c_c·ḋ`(침투 깊이·속도 기반 페널티) + 쿨롱 마찰. 정지 마찰은 **접선 스프링 앵커(stick point)**로 저속 떨림 없이 유지하고(§23.1 10분 정지 안정성·30% 경사 정지), 앵커 힘이 `µ_s·F_n`을 넘으면 운동 마찰 `µ_k·F_n`으로 전환한다.
- **재질 쌍 테이블:** 정지·운동 마찰, 접촉 강성·감쇠(반발 특성), 스파크·사운드 세트를 데이터로 정의한다.
- **CCD:** 300 km/h(83 m/s)에서는 한 스텝에 4.2 cm를 이동한다. 정적 삼각형은 노드 이동 선분과의 정확한 교차 검사로, 움직이는 삼각형은 점-삼각형 연속 충돌 시간(공면 3차 방정식)으로 처리한다. 교차한 노드는 A§4.2의 10단계에서 보정한다. "관통"의 정의는 KICKOFF C2를 따른다.
- **이벤트:** 접촉 에너지와 상대 속도를 기준으로 스파크·파편·먼지·충돌음 이벤트를 큐에 넣어 메인 스레드로 보낸다.

### A§4.7 타이어 (§6) — 하이브리드

- **구조:** 림 노드 링(강체에 가깝게) + 트레드 노드 링 2~3열 + 사이드월 빔 + 내부 압력 삼각형으로 구성된다. 소프트바디 변형이 방지턱·연석을 감싸는 **엔벨로핑**을 자연스럽게 만든다.
- **접지면:** 지면에 닿은 트레드 노드를 모아 접지면 중심·법선·하중(법선 접촉력 합)·길이·폭·노면 재질 혼합(노드 하중 가중, µ-split 포함)을 계산한다.
- **힘:** 허브 각속도와 접지면 속도로 슬립률 κ와 슬립각 α를 구하고, 완화 길이(σ) 1차 지연을 적용한다 → Magic Formula(Pacejka)로 Fx(κ), Fy(α, γ), Mz를 계산한다. 복합 슬립(마찰 타원 가중), 하중 민감도, 캠버 스러스트, 공기압에 따른 코너링 강성·접지면 변화, 구름 저항 `Fr = Crr·Fz`(노면 재질별)를 반영한다. 계산된 힘은 **접지 노드마다 법선 하중에 비례해 분배**한다. 레이캐스트 + 고정 마찰(§25 금지)이 아니다.
- **열·마모:** 트레드 3구역(안·가운데·바깥) 표면 온도 + 코어 온도 + 내부 기체 온도를 계산한다. 온도는 그립 계수 곡선과 이상기체 공기압(P = nRT/V)에 반영된다. 마찰 일에 비례해 트레드 깊이가 줄어든다.
- **수막현상:** 임계 속도 `V_p ≈ 6.35·√p` [km/h, p = kPa] (Horne & Dreher, NASA TN D-2056, 1963)에 수심·트레드 깊이 보정을 적용한다.
- **파손:** 펑크(압력 그룹 누출률), 블로우아웃, 비드 이탈(저압 + 큰 횡력), 림 주행(림 노드 직접 접촉, 낮은 마찰, 스파크, 림 소성변형).
- **참고:** H. B. Pacejka, *Tire and Vehicle Dynamics*, 3rd ed., 2012.

### A§4.8 파워트레인·섀시 (§7~§9)

- 서스펜션은 **실제 링크 지오메트리를 노드-빔으로** 구성한다. 롤센터·캠버 게인·범프 스티어·안티다이브는 공식이 아니라 지오메트리에서 나온다(§7).
- 파워트레인은 1D 회전 자유도 네트워크(엔진 → 클러치 → 변속기 → 디퍼렌셜 → 구동축 → 허브)이며 같은 dt로 적분한다. 구동축은 비틀림 스프링-댐퍼로 모델링해 와인드업과 휠 홉을 재현한다. 클러치는 Karnopp 방식 stick-slip 마찰로 만든다(D. Karnopp, 1985).
- 허브 토크는 허브 노드 쌍에 우력으로 인가해 소프트바디와 결합한다. 엔진 마운트도 빔이어서 가속 시 엔진이 실제로 기운다.
- 전자장치(ABS·TCS·ESC 등)는 센서(휠 속도, 요레이트, 횡G)를 읽어 브레이크·스로틀 명령을 수정하는 제어기다. 차량 데이터에서 탑재 여부와 파라미터를 정의한다.

### A§4.9 공력·물 (§10)

- 삼각형별 평판 모델: 상대 공기 속도 `v_rel`, 면적 `A`, 법선 각도로 항력·양력을 계산한다(`½ρ|v_rel|²A·C(θ)`). 공기 밀도 ρ는 ISA 모델(고도·기온)로 구한다. 윙 각도, 파손으로 인한 형상 변화, 슬립스트림(선행 차량 후류 속도장 근사)이 자동으로 반영된다.
- 물: 수면 아래 삼각형에 정수압 `p = ρ_w·g·h`를 적분하면 부력이 정확히 나오고, 여기에 삼각형별 수중 항력을 더한다. 흡기구 노드의 수심으로 하이드로락을 판정한다.

### A§4.10 손상 → 기능 연동 (§4.4)

- 차량 데이터의 `damageLinks`가 "빔 그룹 상태 → 부품 상태 → 기능 효과"를 정의한다.
  - 예: `radiator` 그룹 파단 비율 > 20% → 냉각수 누출률 → 수온 모델 → 출력 제한 → 과열 고장.
- 부품 상태는 0~1 연속값이다. 경고등, HUD 손상 실루엣, 텔레메트리가 같은 값을 읽는다.

### A§4.11 차량 데이터 포맷 (§4.6)

- 자체 JSON 포맷: `parts`, `slots`, `nodes`, `beams`, `triangles`, `hydros`, `pressureWheels`, `powertrain`, `flexbodies`, `props`, `lights`, `sounds`, `variables`, `damageLinks`, `targets`(KICKOFF C7).
- 로더는 **C++ 코어 안**에 둔다(yyjson). 헤드리스 CLI와 웹이 같은 해석 결과를 얻는다. 스키마(JSON Schema)는 `tools/validate`에서 CI 검증한다.
- 핫리로드: Vite 개발 서버가 `data/` 변경을 감지 → 물리 워커로 JSON 전송 → 해당 차량을 재구성한다(자세·위치는 보존).
- 자세한 명세는 M1에서 `docs/VEHICLE_FORMAT.md`로 작성한다.

```

### A§4.12 노면 (§11)

- 노면은 **거시 형상**(지형 하이트필드 + 도로·시설 메시)과 **미세 요철 함수**(재질별 진폭·파장, 결정론 노이즈)로 이루어진다.
- 변형 가능한 층(자갈·진흙·모래·눈)은 셀별 격자에 층 두께를 저장하고, 타이어 접지 하중·슬립에 따라 결정론적으로 갱신한다. 침하·밀려 쌓임·바퀴 자국을 표현하며, 같은 격자를 렌더러가 읽어 비주얼과 일치시킨다.
- 재질 표(§11.1)는 `data/surfaces/*.json`에 둔다. 한 접지면 안의 여러 재질은 노드 하중으로 가중 합산한다.

## A§5. 렌더링 (§16)

- **기반:** Three.js `WebGPURenderer` + TSL 노드 머티리얼. WebGPU가 없으면 WebGL2 백엔드로 폴백하고 기능을 줄인다.
- **Flexbody 변형(§4.5):** 빌드 타임에 비주얼 정점을 가까운 노드 3~4개의 로컬 좌표계에 바인딩한다(가중치 포함). 런타임에는 보간된 노드 버퍼를 업로드하고 컴퓨트 셰이더로 정점을 변형한다 → 정점 인접 목록으로 노멀·탄젠트를 재계산한다(원자 연산 없는 gather). 찢어진 경계는 파단 빔을 기준으로 바인딩을 분리한다.
- **머티리얼:** PBR. 카 페인트는 `MeshPhysicalNodeMaterial`(베이스 + 플레이크 노이즈 + 클리어코트 + 이방성)로 만든다. 유리는 굴절·먼지·빗방울, 브레이크 디스크는 온도에 따른 흑체 발광을 표현한다.
- **조명:** Hillaire(2020) 대기 산란 LUT(컴퓨트)로 하늘을 만들고, 시간에 따라 IBL을 재생성한다. GI는 프로브 조도 볼륨(맵 베이크) + SSGI/GTAO, 반사는 SSR + 반사 프로브, 그림자는 CSM이다. 자동 노출과 AgX 톤매핑을 쓴다.
- **후처리:** TRAA, 블룸, 모션 블러, DOF(포토·리플레이), 절제된 렌즈 플레어. 필름 그레인·색수차는 기본으로 끈다.
- **날씨:** 컴퓨트 파티클 비·눈, 젖은 노면(거칠기·반사·웅덩이 마스크), 유리 빗방울(와이퍼 연동), 차체 적설.
- **규모:** 지형은 CDLOD, 건물은 HLOD 임포스터, 소품은 `BatchedMesh`/`InstancedMesh`로 그린다. 스키드마크는 링 버퍼로 개수 예산을 관리한다.
- **웹 한계로 인한 차이:** Lumen·Nanite·VSM·DLSS/FSR2/XeSS·HW 레이트레이싱은 없다. 업스케일은 TRAA + 동적 해상도로 한다. 영상 내보내기(§18.3-11)는 WebCodecs `VideoEncoder` + MP4 먹서를 쓰고, 오프라인 렌더링이라 실시간보다 느릴 수 있다.

## A§6. 월드·스트리밍 (§13, §21.4)

- **셀 그리드:** 256 m × 256 m 셀 + LOD 링. 셀 데이터는 하이트필드 타일, 도로 그래프 조각, 정적 메시 인스턴스, 충돌 BVH blob, 노면 재질 맵, 소품 인스턴스로 구성된다.
- **베이크 파이프라인(`tools/map-bake`):** 지형(DEM 또는 침식 시뮬레이션) → 도로 스플라인 + 단면 프로파일 → 절토·성토 정합 → 절차적 건물·소품 → 셀 분할 → 압축 바이너리.
- **런타임:** 스트리밍 워커가 차량 속도에 비례한 반경으로 셀을 미리 가져온다. 물리 충돌 셀은 렌더보다 먼저, 더 좁은 반경으로 적재한다.
- **파괴 가능 소품:** 평소에는 정적으로 "잠들어" 있다가 접촉 광역 단계에서 활성 노드-빔 섬으로 승격된다.
- **AI 교통과 물리 LOD(§21.4):** 차선 그래프를 따라 주행한다. 먼 차량은 저해상도 노드-빔 또는 강체 + 간이 타이어로 돌리고, 충돌 가능 거리에 들어오기 전에 고해상도로 상태를 이전한다.
- **자동 검증 봇(§13.4):** 헤드리스 CLI + 맵 데이터로 모든 도로를 자율 주행해 주행 불가 지점, 충돌 누락, 떠 있는 오브젝트, 도로-지형 틈을 보고한다.

## A§7. 오디오 (§17)

- Web Audio 그래프 + AudioWorklet이다. 엔진음은 실린더 배치·점화 순서·배기량·과급 파라미터로 만드는 절차 합성이다(녹음 샘플이 조달되면 그래뉼러 크로스페이드로 확장).
- 타이어는 슬립·하중·노면에 따른 대역 노이즈 합성, 충돌은 접촉 이벤트로 구동하는 모달 합성(금속·유리·플라스틱)이다.
- 공간 음향은 거리 감쇠·도플러·차폐 필터, 터널·도심 리버브(생성 IR 컨볼루션)로 처리한다.
- 믹서 버스: 엔진·타이어·충돌·환경·UI·음악, 야간 모드(다이내믹 레인지 압축).

## A§8. 입력 (§15)

- 장치 계층: 키보드·마우스, Gamepad API(패드·휠 축), Pointer Events(터치) → 액션 매핑(데이터, 리매핑·중복 경고) → **원시 입력만** 물리로 보낸다.

- FFB: 코어가 셀프얼라이닝 토크 등 FFB 채널을 계산해 텔레메트리로 내보낸다. 출력은 데스크톱 래퍼(Tauri/Electron + SDL3)가 맡는다(KICKOFF Q4).

## A§9. UI (§18)

## A§10. 리플레이·저장·모딩 (§21.5, §21.6)

## A§12. 성능 예산 (§21.7)

- 기준 실측(KICKOFF §1): 빔 계산만으로 WASM 차량 1대·1스텝에 0.21 ms, 네이티브에서 0.13 ms가 든다.
- **스텝 예산:** RTF 1.0이면 스텝(0.5 ms)마다 모든 섬 처리가 끝나야 한다. 1차 목표는 풀해상도 차량 1대·1스텝의 전체 비용(빔 + 충돌 + 타이어 + 파워트레인)을 WASM 기준 ≤ 0.35 ms로 맞추는 것이다(수작업 SIMD128로 빔 커널 1.5~2.5배 가속 목표).
- **과부하 정책(§21.2, §25):** 스텝을 절대 건너뛰지 않는다. 벽시계 대비 시뮬레이션 시간을 느리게 흘리고 RTF를 HUD·프로파일러에 표시한다.
- **렌더 예산:** 1440p 60 fps(16.6 ms) 기준으로 메인 스레드 게임 로직 ≤ 3 ms, GPU ≤ 14 ms. 사용자 PC 측정으로 검증한다(KICKOFF Q3).

## A§13. 확장 대비

- **멀티플레이(§19 [선택·후순위]):** 서버 권위 구조. 결정론 코어 + 입력 동기화, 또는 노드 상태 양자화·델타 압축 동기화. 지금은 섬 상태 직렬화 API만 만들어 둔다.
- **모바일(§15.4):** 물리 LOD 단계와 렌더 품질 프리셋으로 대응한다. 터치 조작은 입력 계층의 장치 하나로 추가한다.
- **UE5 이식:** 코어의 C ABI(`bindings/`)를 UE 플러그인이 감싸는 구조로, 같은 코어를 쓸 수 있다.
