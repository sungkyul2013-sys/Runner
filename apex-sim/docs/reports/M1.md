## 테스트

- 코어 네이티브: **56/56**(`npm run core:test`), WASM(Node): 같은 스위트, 네이티브와 해시 일치(`npm run core:test:wasm`)
- 웹 단위: 7/7(`npm test`)
- E2E(`npm run test:e2e`, 헤드리스 Chromium, WebGL2 — KNOWN_ISSUES W1): 브라우저 골든 해시 = 네이티브, 샌드박스·차고 스크린샷, **주행**(E2E_DRIVE)

새 테스트:
- `Porsche 911 Turbo: a wall crash in the drive scene keeps the energy books` — 90 km/h 전속 벽 충돌, 튕김·착지 포함 수지 오차 < 최대 운동에너지의 3%(측정 0.7%)
- `a node pressed onto the ground keeps sliding when CCD clamps it` — CCD 수정 전 코드에서는 노드가 제자리에 얼어붙어 실패(재현 확인), 수정 후 통과

## 이번 단계에서 찾아 고친 물리 결함

- **CCD 동결**: 스텝마다 지면 아래로 눌리는 노드를 CCD가 충돌 시점으로 되감으면서 접선 이동까지 지웠다. 노드는 멈추고 접선 속도만 수백 m/s로 커져, 빔 감쇠가 0.1초 만에 23 MJ을 차에 넣었다(벽 충돌 후 착지하던 트레드 노드). 이제 끝점을 표면에 투영해 침투만 지운다
- 주행 씬 콘이 노드 반경만큼 땅에 묻혀 생성돼 첫 스텝에 30 m 튀어 오름
- 램프 쐐기 아랫면(한쪽 면 삼각형)이 트레드 노드를 아래로 끌어 에너지 폭주

## 웹 주행과 호스팅

- 주행 모드: 코어 차량 스폰(JSON)·입력·텔레메트리, GLB 차체를 섀시 좌표계에, 휠을 물리 허브에 결합(차체 변형 표시는 M2 flexbody)
- **교차 출처 격리 없는 페이지 대응**: SharedArrayBuffer가 없으면 단일 스레드 WASM(`sbc-st`)과 슬롯 버퍼 전송(메시지 트랜스포트)으로 돈다. 정적 서버(격리 없음)에서 포르쉐가 5초에 약 110 km/h, 물리 스텝 0.33 ms(예산 0.5 ms), 실시간 배율 0.95
- 아티팩트 패키지(`tools/artifact/package-app.mjs`): 해시 경로(#drive 기본·#garage·#sandbox), GLB는 base64 텍스트, 글꼴은 Google Fonts

## 차량 모델(사용자 Crash Lab 모델 기준 재설계)

- 휠 아치 실측으로 휠 크기·위치 맞춤(`fitWheels`), 절차 휠(고스트 7 트윈 스포크, 마이바흐 20 스포크) + 디스크·캘리퍼
- 마이바흐 GLS: 23인치(285/40 R23)로 차고 118 mm 낮춤, 휠베이스 3.47 → 3.144 m(실차 3.135 m). 베이크에 없던 앞유리·파노라마 루프·뒷유리를 막면으로 채움, 그릴·흡기구 백킹, 헤드램프(다크 크롬 하우징 + 주간주행등)·테일램프(적색 렌즈 + 스모크 상단) 발광
- 차고 아티팩트: 세 차를 앱 렌더러로 보는 3D 뷰어, 마이바흐 수정 전후 비교
