# 수 국어논술 — 모바일 학습 앱

`index.html` + `app/`. 소개 페이지가 아니라 **실제로 문제를 풀고, 첨삭을 직접
해보고, 학습 플랜을 만드는 앱**입니다. 프레임워크 없이 Vite + TypeScript로
만들었고, 3D 레이어만 Three.js를 씁니다.

> 이 저장소에는 세 개의 진입점이 있습니다.
> **`index.html`** → 이 앱 · **`story.html`** → 이전 스크롤형 소개
> 사이트(`story/`) · **`game.html`** → 원래 러너 게임(`src/`).
> 셋 다 `npm run build` 한 번으로 빌드됩니다.

## 실행

```bash
npm install
npm run dev            # http://localhost:5173  (/story.html, /game.html)
npm run build          # tsc --noEmit + vite build → dist/
npm run build:site     # → su-academy.html (앱, 단일 파일)
npm run build:story    # → su-story.html   (소개 사이트, 단일 파일)
```

## 프로그램 체험 (`app/views/trial.ts`)

홈 첫 화면의 기본 동작입니다. 화면들을 각각 눌러 보게 두면 방문자가 이야기를
직접 조립해야 하니, **학원이 실제로 하는 순서를 한 흐름으로** 돌립니다.

```
학년 확인 → 진단 12문항 → 영역별 분석 → 4주 설계 → 상담 신청 → 접수 완료
```

각 단계가 다음 단계에 결과를 넘깁니다. 진단 점수에서 취약 영역이 나오고, 그
영역이 분석 문구와 추천 과정을 정하고, 학년·목표가 4주 플랜을 만들고, 그
전부가 상담 메모에 이미 적혀 있습니다. 이름과 연락처만 남기면 끝납니다.

퀴즈 엔진은 **복제하지 않고 그대로 끼워 넣습니다** — `quizView(router,
onFinish)`에 완료 콜백을 주면 결과만 저장하고 제어를 돌려줍니다. 상담 폼도
`consultForm(onSent)`로 분리해서 흐름 안에서 마무리됩니다.

상단에 5단계 진행 표시가 고정되고(완료는 초록, 현재는 첨삭 빨강), 흐름 상태는
모듈 스코프에 있어 중간에 다른 탭을 눌렀다 돌아와도 같은 단계에서 이어집니다.

## 학습 시스템 (`app/views/study.ts`, `app/data/curriculum.ts`)

정규 과정은 **6단계 24회차**입니다(문장 → 문단 → 요약 → 근거 → 반론 → 한 편).
같은 과정을 두 가지로 봅니다.

- **날짜** — 시작일과 요일을 고르면 24회차가 달력에 깔립니다. 오늘 분량,
  이번 주 완료 수, 다음 수업일이 한 화면에 있고, 달을 넘겨 걸어 다닐 수
  있습니다.
- **단계** — 6단계 사다리. 단계마다 목표와 **통과 조건**이 있고, 앞 단계를
  3회차 이상 마쳐야 다음 단계가 열립니다.

핵심은 **시간표를 저장하지 않는다**는 점입니다. 저장하는 것은 시작일·요일과
회차별 완료 여부뿐이고, 날짜는 커리큘럼 순서를 고른 요일에 나눠 주는
`buildSchedule()`이 매번 계산합니다. 그래서 시작일을 바꿔도 배운 기록은 그대로
남고, 두 벌의 일정이 서로 어긋날 일이 없습니다.

회차 종류마다 갈 곳이 다릅니다 — **문제·점검**은 진단 화면, **첨삭**은 첨삭
랩으로 넘기고, **쓰기**는 시트 안에서 바로 씁니다. 쓰기 칸은 원고지처럼 줄이
그어져 있고, 목표 글자 수까지 남은 양을 세면서 **입력 중 자동 저장**합니다
(공백 제외, 400ms 디바운스). 글을 한 번 날리면 그 회차는 통째로 날아가니까요.

달력은 날짜 칸마다 회차 종류를 점 색으로 찍고, 그날 회차를 다 마치면 칸에
초록 테두리가 남습니다. 보고 있던 달과 고른 날짜는 모듈 스코프에 있어서,
회차를 완료해 화면이 다시 그려져도 그 자리에 머뭅니다.

## 한국어 조사 (`app/core/hangul.ts`)

런타임에 문장을 조립하면 조사가 틀립니다 — "어휘이 과제입니다"는 한국어를 읽는
모든 사람에게 고장으로 보입니다. 마지막 음절의 받침 유무로 이/가, 은/는을
고릅니다(조립 음절은 `(초성×21 + 중성)×28 + 종성` 배치라 28로 나눈 나머지가
받침입니다).

## 스크롤 쇼케이스 (`app/views/showcase.ts`)

홈 화면 아래로 계속 스크롤하면 **제품 소개 형식의 긴 챕터**가 이어집니다.
앱 화면이 카드와 표면으로 이뤄져 있다면, 이쪽은 바탕과 타이포만으로
구성해서 성격 전환이 설명 없이 느껴지도록 했습니다.

| 챕터 | 성격 | 3D |
| --- | --- | --- |
| 01 여는 화면 | 먹 | `수` 글자 |
| 02 **핀 고정 스테이지** | 먹 | 원고지 → 책 → `수` (3비트) |
| 03 첨삭 전/후 | 한지 | — |
| 04 선생님 (윤원수 원장) | 먹 | 구 |
| 05 숫자 | 먹 | 물결 |
| 06 **가로 스크롤 과정** | 먹 | 나선 |
| 07 마무리 | 한지 | — |

핵심은 **페이지 바탕이 챕터를 따라간다**는 점입니다. 먹 챕터는 배경을 비워
두고 `body`를 어둡게 만들어서, 파티클 레이어가 상자 없이 화면 전체에
드러납니다. 상단 바와 탭 바도 같은 규칙으로 색이 뒤집히고(토큰을 바에
재정의), 마지막 챕터는 문서 끝까지 한지 색이 이어져 앱 바탕이 비치는 자투리가
남지 않습니다.

핀 고정 스테이지는 스크롤 진행률을 3비트로 나눠 문구를 교차 페이드하고
3D 형상을 바꿉니다. `morph()`는 **같은 형상 요청을 무시**하기 때문에 매
프레임 안전하게 다시 선언할 수 있고, 그래서 위로 되돌아왔을 때도 해당
챕터의 형상이 복원됩니다.

가로 스크롤 과정은 이동 거리를 **매번 새로 측정**합니다. 섹션이 라우터에
붙기 전에 만들어지므로 생성 시점에 캐시하면 떨어져 있는 요소의 좌표를 재게
되고, 기준도 뷰포트가 아니라 핀 컨테이너입니다(데스크톱은 좌측 레일 폭만큼
다릅니다).

## 문제 풀이 시스템 (`app/data/questions.ts`, `app/views/quiz.ts`)

4영역(**어휘 · 독해 · 교정 · 구성**) 12문항이고, 응답 방식이 셋입니다.

- **choice** — 선택지 고르기 (어휘·독해)
- **tap** — 문장에서 **틀린 부분을 눌러** 찾기 (교정)
- **order** — 개요를 **끌어서 순서 배열** (구성)

정답 확인 즉시 해설이 열립니다. 진단은 채점이 아니라 학습이라, 틀린 문항의
이유를 그 자리에서 읽게 했습니다. 채점 결과는 영역별로 집계되어 결과 화면의
막대와 **추천 과정**으로 이어집니다.

진행 중 다른 탭으로 이동했다 돌아와도 이어서 풀 수 있게, 세션 상태는 모듈
스코프에 둡니다.

## 첨삭 랩 (`app/views/lab.ts`)

중2 학생 글의 문장을 눌러 **문제 유형을 고르면** 표시가 남고, 채점을 누르면
선생님 첨삭과 대조합니다. 채점은 정직하게 매깁니다 — 자리를 맞히면 만점,
이유가 다르면 절반, **멀쩡한 문장에 표시하면 감점**입니다. 마지막에 선생님이
다시 쓴 글을 보여 줍니다.

## 터치 인터랙션 (`app/core/sortable.ts`, `app/core/ui.ts`)

Pointer Events 하나로 마우스·터치·펜을 함께 처리합니다.

- **끌어서 정렬** — 행 전체가 손잡이입니다(폰에서 20px 그립은 놓치기 쉬움).
  행에 `touch-action: none`을 줘서 세로 드래그가 스크롤로 새지 않습니다.
- **스와이프** — 답을 확인한 뒤 카드를 좌우로 밀어 이동. 세로 성분이 크면
  무시해서 스크롤과 충돌하지 않습니다.
- **바텀 시트** — 손잡이를 잡고 아래로 던지면 닫힙니다. 720px 이상에서는
  같은 컴포넌트가 **가운데 다이얼로그**로 바뀝니다.
- **햅틱** — 선택·정답·오답에 진동 패턴(안드로이드/크롬. iOS Safari는 미지원
  이라 무시됩니다).

## 반응형 템플릿

모바일이 기본이고, 브레이크포인트는 **열을 더할 뿐 재배치하지 않습니다**.

| 폭 | 바뀌는 것 |
| --- | --- |
| 기본 | 한 열, **하단 탭 바**, 타일 2×2 |
| ≥ 600px | 타일 4열, 주간 플랜 3열 |
| ≥ 900px | 탭 바 → **좌측 레일**, 퀴즈 카드 폭 고정, 여백 확대 |
| ≥ 720px | 바텀 시트 → 가운데 다이얼로그 |
| ≥ 1180px | 홈이 **히어로 열 + 카드 열** 2단, 히어로는 sticky |

글자 크기는 전부 `clamp()`라 브레이크포인트 없이 흐릅니다. 안전 영역
(`env(safe-area-inset-*)`)은 상단 바·탭 바·시트·토스트에 모두 반영했습니다.
입력 글자는 16px 이상이라 iOS에서 포커스 시 확대되지 않습니다.

## 테마

토큰이 의미 단위(`--bg`, `--surface`, `--text` …)라 **밝게/어둡게/시스템**을
전부 지원합니다. 스탬프가 없는 기본 상태는 `prefers-color-scheme`이 결정하고,
상단 바 버튼으로 시스템 → 밝게 → 어둡게를 순환하며 선택은 저장됩니다.
`theme-color` 메타도 함께 바뀝니다.

## 저장 (`app/core/store.ts`)

`localStorage` 한 키에 테마·진단 기록(최근 20회)·첨삭 랩 최고점·플랜·시간표
(시작일과 요일)·회차별 완료·쓰기 원고·연속 학습일을 담습니다. 예전 저장본에
없던 항목은 "아직 아무것도 안 함"으로 채워 읽습니다. 사파리 시크릿 모드처럼
쓰기가 막힌 환경에서는 **동작은 하되 기억만 못 하도록** 예외를 삼킵니다.

날짜는 전부 `app/core/dates.ts`가 **로컬 달력**으로 다룹니다. `toISOString()`은
UTC로 바꿔 버려서, 서울에서 저녁에 한 학습이 어제 날짜로 기록됩니다.

## 학습 맵 (`app/views/map.ts`)

레벨·XP·스테이지·배지가 전부 **실제로 한 일에서 파생**됩니다. 별도 진행도
상태를 저장하지 않기 때문에 기록과 어긋날 수가 없습니다.

- XP = 진단 회차마다 `10 + 맞힌 수 × 5`, 첨삭 최고점의 절반, 플랜 저장 30,
  **정규 과정 회차 × 12**, **단계 통과 × 40**, 연속 학습일 × 15
- 스테이지 11개는 각각 열림/완료 조건이 함수로 붙어 있고, 잠긴 스테이지도
  **누를 수 있습니다** — 왜 잠겼는지 알려주는 게 맞아서 `aria-disabled`를
  쓰지 않고 "잠김" 라벨로 상태를 읽힙니다.

## 3D 레이어 (`shared/three/`)

두 겹입니다.

- **`Solids.ts` — 단단한 층.** 라운드 박스 하나를 `InstancedMesh`로 찍어
  `수` 마크, 원고지 격자, 책 더미, 연필, 탑을 만듭니다. 3점 조명(차가운 키 ·
  따뜻한 필 · 붉은 림)과 톤 매핑을 걸어 실제 재질처럼 보입니다. 드로우 콜은
  하나라 폰에서도 가볍습니다.
- **`Field.ts` — 공기.** 입자는 이제 주역이 아니라 주변 먼지라 개수와
  불투명도를 크게 줄였습니다.

형상마다 `SOLID_POSE`에 각도·크기와 **`y` 오프셋**이 있어, 같은 화면을 쓰는
본문에 가려지지 않도록 들어 올립니다. 모양이 부족한 인스턴스는 크기 0으로
대기시킵니다 — 예전처럼 여분 블록을 안쪽에 채우면 `수`의 속공간이 메워져
글자가 덩어리로 보였습니다.

밝은 테마에서는 불투명도를 낮추고 카드에 `backdrop-filter`를 걸어 가독성을
지킵니다. WebGL을 못 쓰면 레이어만 제거되고 앱은 그대로 동작합니다.

## 교체해야 할 내용

**연락처·수치·인물·후기는 전부 예시 데이터입니다.**

- 주소·전화·상담 시간 (`app/views/apply.ts`)
- 선생님 정보 (`app/data/content.ts`의 `TEACHER`) — 현재 **윤원수 원장**
- 과정 내용·정원 (`app/data/content.ts`)
- 문항 (`app/data/questions.ts`) — 실제 교재 문항으로 교체 가능
- 상담 폼은 **전송되지 않습니다.** `app/views/apply.ts`의 submit 핸들러에
  `fetch`를 붙이면 연결됩니다.
